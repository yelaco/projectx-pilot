# Project rules
- Run go test ./... and go vet ./... after each phase; no real credentials in tests.
- Default to read-only; never add an execution path without explicit arming, risk checks, reconciliation, and durable idempotency.
- All broker traffic originates directly on the user's personal laptop without a proxy, tunnel or cloud relay. Explicitly configured authenticated HTTPS dashboard controls may arrive through Cloudflare Tunnel and Access; remote Start/Pause/review/Flatten use the same execution safeguards as local controls. Configuration and broker credentials stay on the laptop.
- TradingView defaults to local review. Automatic execution requires configured exact profile/account scope and an explicit authenticated dashboard Start; it stays disabled otherwise. The operator is responsible for confirming provider permission; the application does not require a support ticket/reference. A user-started continuous runner may enter subsequent verified sessions only after fresh flat-account/risk reconciliation.
- Verify API behavior against official documentation; record uncertainty and fail closed.
- Accept verified one-way or reciprocal OCO sibling links; never infer linkage from prices alone. Preserve the first management trigger before emergency progress overwrites the display.
- Local repair of the legacy reciprocal-only OCO false alarm requires explicit password-confirmed review, matching closed one-contract history, two fresh flat/no-order observations, and an atomic scoped audit. Never clear daily locks/uncertain intents, arm, or replay as part of repair.
- Never retry ambiguous order placement. Missing protection blocks entries and invokes the documented attention-only fail-safe; never automatically close exposure or cancel protective orders.
- A restart or reconnect does not establish flatness. Session/holiday uncertainty blocks execution. Per-trade-only policies intentionally do not calculate or enforce MLL; never represent this as verified floor protection.
- Keep credentials, tokens, response bodies, and signal payloads out of logs.
- Use context cancellation, bounded I/O, UTC timestamps and America/Chicago session rules.
- Document actual implemented behavior separately from planned phases.
- Stored Trade Manager policies are configuration, never proof of enforced limits; multi-account targets must never be silently reduced to one account.
- Existing administrator stores override bootstrap/environment credentials. Never restore revoked logins or log passwords, hashes, or CSRF seeds.
- Dashboard automation profiles are webhook-only. Practice API tests never require or create an automation profile. Retired manual JSON import routes cannot dispatch orders.
- Keep UI/risk bracket distances positive; encode signed wire price offsets (BUY stop negative/target positive; SELL stop positive/target negative). Never apply direction twice or retry an old rejected signal.
- Manual Market/Limit tickets share the execution engine; exact quantities must fit risk, never be silently resized. Preview is not submission.
- Automatic write support includes API-verified simulated Practice, Trading Combine and Express Funded accounts; Live Funded is unsupported by Topstep API. Manual Practice test tickets remain PRAC-only. Account identity for automation uses pinned numeric ID, not a name prefix, with verified ordinary-session hours (operator-confirmed session windows or the reviewed, bounded continuous calendar). Legacy policies require a known fixed floor; per-trade-only policies require no floor. Merged holiday sessions deny arming.
- Hold the process execution lease before workers/listeners. Recovery never restores arming or replays placement; emergency mutation latches must survive restart.
- Automatic deliveries are durably claimed once before dispatch. Never replay a claim after interruption; pre-arming/disarmed alerts must not fire later. Review-only profiles remain separate.

- Automatic execution is account-scoped: one running profile owns an account; distinct accounts run independently. Keep the SQLite one-active-intent-per-account constraint and never restore the global active-intent index.
- Freeze and atomically claim every target before fanout. Independent outcomes are not an atomic broker transaction; never undo accepted targets or replay blocked/interrupted ones.
- Unix datagrams carry wake hints only after inbox commit. SQLite remains authority; socket loss falls back to bounded scans. Never accept account, credentials or execution authority through a socket notification.
- Share JWT, contract subscriptions and request governor. Never cache fresh exposure/risk checks merely to reduce entry latency; preserve mutation budget under the documented API ceiling.

- Instrument scope belongs to each automation profile and its pinned contract. Do not restore a global instrument allowlist. Ignore legacy allowed_instruments YAML; manual Practice contracts must come from active authoritative discovery. Calendar/risk/protection checks remain mandatory.

- Trade Managers own recurring Chicago start/last-entry/exit-reminder schedules (legacy field name: flatten). Reaching the exit reminder pauses entries and reports attention; it never automatically flattens. Do not use ticker names as calendar permissions. Intersect manager windows with verified authorization and reviewed holiday caps; never widen them or infer an unknown year's holidays. Schedule edits pause affected profiles and preserve existing intents' captured windows.

- Established positions are operator-controlled. Persist last verified exposure as historical evidence across restart; never treat it as fresh flatness or permission to trade. Only an explicit authenticated dashboard emergency Flatten action can close positions or cancel protective orders. Monitoring faults, protection mismatches, risk thresholds, clocks, news and scheduled reminders only pause/report; broker SL/TP remains untouched. Automatic cancellation is limited to wholly unfilled entry parents with no observed or previously verified exposure.
- Optional Discord webhooks carry sanitized outbound attention reports only, are disabled by default, use private credentials and bounded nonblocking delivery, and never grant execution authority.

- Reviewing a closed historical stale-quote lock may retain current broker positions/orders only after a separate password-confirmed acknowledgement bound to a short-lived account/intent/session/observation token and two fresh matching observations. Audit the exact acknowledgement atomically; never clear unresolved intents or other lock reasons, adopt positions, arm, close/cancel, or replay alerts.
- Daily trading reports use an independent optional Discord webhook at 16:15 America/Chicago, reporting the previous 17:00 through current 16:00 window. Use read-only account-wide trade legs, exclude voided legs, sum costs across opening/closing legs, and distinguish unavailable costs/data from zero. Durably claim each account/date before delivery; never mix report permissions with trading authority or silently omit configured targets.
- Shared account-fault review must classify every fixed lock reason, require explicit password-confirmed reason/account/intent/session/snapshot-bound acknowledgement and two fresh matching observations, and atomically update acknowledgement metadata only. Active uncertain/submitting orders and unresolved emergency attempts cannot be acknowledged away; daily-loss/trade-count/liquidation locks are non-overridable. Preserve risk locks against later technical overwrites, original triggers, ownership, active-intent constraints and all mutation/claim latches. Acknowledgements cover only the exact continuing fault/exposure and expire on recovery or changed exposure; restart never arms or replays.
- System health is a read-only checklist of existing telemetry/caches, never a new broker/Discord probe or execution permission. Separate current check results, retained locks and historical triggers; unknown/stale observations and acknowledged faults must not imply verified protection. Preserve narrow authenticated exports and show browser-refresh failures as stale.

- Remote dashboard access is opt-in and exact-host scoped, loopback-origin only, and requires verified Cloudflare Access RS256 signature/issuer/audience/expiry/allowed-email plus existing app authentication and CSRF/password checks. Never trust forwarding headers as authority, expose the dashboard on the webhook route, or route broker traffic through Cloudflare. Local recovery remains available when Access is unavailable.

- Installation is portable and has no machine-specific activation flag. Never assume the current development environment is the intended execution host or start its services merely to test deployment; prepare a private bundle when the user chooses deployment elsewhere.

- A user-started continuous profile may resume after an in-process technical pause only after resolved terminal history, two fresh flat/no-order observations and fresh account/market/session/risk checks. Retain Start intent in memory only; manual Pause, emergency Flatten, configuration revocation and restart cancel it. Automatic technical-lock release requires exact closed same-Start/account/profile/contract/session evidence and an atomic recovery audit; never waive risk/ambiguous/unknown/legacy-repair locks, acknowledge continuing faults automatically, change exposure/protection, or replay blocked deliveries.

- Multi-account routing defaults to Copy. Explicit round-robin distribution freezes the full authorized candidate scope, skips known unavailable targets, and atomically claims one target with a durable manager-scoped cursor. No-ready alerts are durably blocked without advancing; unassigned account-zero outcomes never reach an engine/API. Never reassign after selected-account failure, advance on duplicates, replay interrupted/blocked alerts, or let mode changes expand a prior delivery. Fresh selected-account broker/risk/session checks remain mandatory.

- Optional multi-account risk overrides replace the manager default only for explicitly selected accounts. Validate positive finite amounts and deep-clone maps; freeze each account’s effective policy before arming. Default/override edits pause affected profiles and preserve active intents. Never round a below-one-contract budget up, alter another account’s sizing, silently erase omitted settings, or reroute a rejected distributed signal.
